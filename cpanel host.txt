PART 1: HOW TO UPDATE THE FRONTEND (NEXT.JS)
================================================================================
Use this workflow whenever you change UI components, text, pages, or styles.

STEP 1.1: Build the static frontend locally
--------------------------------------------------------------------------------
Open a terminal in your project root and run:
   cd front-end
   npm run build
   cd ..

(This compiles and exports your Next.js application into the "front-end/out" directory).

STEP 1.2: Generate the upload zip
--------------------------------------------------------------------------------
Run the helper PowerShell script located in the scratch directory:
   powershell -ExecutionPolicy Bypass -File .\scratch\zip_frontend.ps1

This automatically generates:
   frontend-public_html.zip (inside your root directory)

STEP 1.3: Upload and deploy in cPanel
--------------------------------------------------------------------------------
1. Log into your cPanel (https://new.athulenergy.com:2083).
2. Open "File Manager" and double-click into "public_html".
   *** CRITICAL: NEVER DELETE THE "api" FOLDER INSIDE public_html ***
3. Click "Upload" in the top cPanel toolbar.
4. Drag and drop "frontend-public_html.zip".
5. Back in File Manager, click "Reload".
6. Right-click "frontend-public_html.zip" and choose "Extract".
   Confirm the target folder is "/public_html".
7. Click "Extract File(s)", then close the popup.
8. Delete the "frontend-public_html.zip" from public_html to save server space.
9. Verify that public_html/.htaccess has the Passenger bypass rules (see PART 4).

Your frontend changes are immediately live! Hard-refresh your browser (Ctrl + F5).

PART 2: HOW TO UPDATE THE BACKEND (EXPRESS / SEQUELIZE)
================================================================================
Use this workflow whenever you modify backend routes, controllers, or database models.

STEP 2.1: Generate the backend zip
--------------------------------------------------------------------------------
Run the helper PowerShell script in your project root:
   powershell -ExecutionPolicy Bypass -File .\scratch\zip_backend.ps1

STEP 2.2: Upload and deploy to cPanel

3. Return to File Manager, right-click "athul-backend-deploy.zip", and choose "Extract".
   Target: "/athul-backend".
4. Delete "athul-backend-deploy.zip".

STEP 2.3: Restart the Node.js application
--------------------------------------------------------------------------------
1. In cPanel Home, search for and open "Setup Node.js App".
2. Next to "new.athulenergy.com/api", click "RESTART".
   *(NOTE: Only if you added brand new npm packages to package.json, scroll down
   and click "Run NPM Install" first before clicking RESTART).*

Verify the backend by opening:
   https://new.athulenergy.com/api/health
It should return: {"status":"healthy", ...}

PART 4: DISASTER RECOVERY & CONFIGURATION REFERENCE
================================================================================

A) WHAT IF https://new.athulenergy.com/api/health SHOWS 404?
--------------------------------------------------------------------------------
This means the Passenger bridge file was accidentally removed during a frontend
cleanup. Recreate it in 30 seconds:

1. Inside "public_html", check if the folder "api" exists. If not, create it:
   Folder name: api
2. Inside "public_html/api/", create a file named: .htaccess
3. Put these exact 5 lines into "public_html/api/.htaccess":
   PassengerAppRoot "/home/newathulenergy/athul-backend"
   PassengerBaseURI "/api"
   PassengerNodejs "/home/newathulenergy/nodevenv/athul-backend/22/bin/node"
   PassengerAppType node
   PassengerStartupFile server.js
4. Save the file, go to "Setup Node.js App", and click "RESTART".


B) WHAT SHOULD BE IN "public_html/.htaccess" (ROOT HTACCESS)?
--------------------------------------------------------------------------------
The main .htaccess in public_html MUST contain the following lines right below
"RewriteBase /" so Apache allows Passenger to handle /api:

   # Pass API and Media requests directly to Passenger Node.js
   RewriteRule ^api - [L]
   RewriteRule ^media - [L]

PART 5: HOW TO SWITCH FROM STAGING (new.) TO MAIN DOMAIN (athulenergy.com)
================================================================================
When the client approves the staging site and is ready to switch to the primary
domain (athulenergy.com), the transition is smooth because all code is already
built for athulenergy.com:

1. FRONTEND:
   - All canonical URLs, sitemaps, robots.txt, and metadataBase were ALREADY
     pre-configured for "https://www.athulenergy.com".
   - The frontend API calls use relative paths ("/api"), which automatically
     adapt to whichever domain is loaded.
   - Simply upload "frontend-public_html.zip" into the main domain's document
     root (usually public_html for the primary domain in cPanel).

2. BACKEND CPANEL NODE.JS APP:
   - In cPanel "Setup Node.js App", edit the application:
     Change "Application URL" dropdown from "new.athulenergy.com" to "athulenergy.com"
     Keep URI as "api".
     Click SAVE, then click RESTART.

3. BACKEND .env:
   - In "athul-backend/.env", update line 4:
     CLIENT_URL=https://www.athulenergy.com
   - The server.js CORS already has both "https://athulenergy.com" and
     "https://new.athulenergy.com" pre-whitelisted, so no code change is needed.

4. RE-RUN MEDIA SYMLINK (IF NEEDED):
   - In cPanel Terminal, link the media directory for the primary domain:
     ln -s /home/newathulenergy/athul-backend/media /home/newathulenergy/public_html/media

That's it! Your primary website will be 100% live with all SEO, database,
and dashboard features operational.
